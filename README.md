# babplanner-admin

밥플래너 관리자 웹.

Spring 백엔드의 `/api/v1/admin/**` 을 그대로 쓴다. 관리자 전용 인증 API는
따로 없고, 사용자 앱과 같은 로그인 API를 쓰되 `role`이 `ADMIN`인 계정만
화면에 들어올 수 있다.

## 요구 환경

- Node 20 이상 (개발은 20.16 기준)
- 백엔드가 떠 있어야 한다. 이 앱은 자체 데이터를 만들지 않는다.
- 관리자 계정이 있어야 한다. 일반 회원가입으로는 만들 수 없고, 서버의
  `bapplanner.dev-admin` 설정이나 운영 절차로 만든다.

## 설치와 실행

```
npm install
npm run dev      # http://localhost:5173
```

개발 서버는 `/api` 요청을 백엔드로 중계한다. 브라우저 입장에서는 같은
출처라 CORS 설정이 필요 없다. 백엔드는 이 앱 때문에 수정하지 않는다.

## 환경 변수

`.env.example` 을 복사해 쓴다. **여기 들어가는 값은 전부 브라우저 번들에
그대로 실린다.** 서비스 토큰, JWT 서명 키, DB 비밀번호를 `VITE_*` 로 두면
안 된다.

| 이름 | 뜻 |
|---|---|
| `VITE_API_BASE_URL` | 배포에서 API 서버 주소. 비우면 같은 출처의 상대 경로 |
| `VITE_DEV_API_TARGET` | 개발 서버가 `/api` 를 넘길 곳 (기본 `http://127.0.0.1:8080`) |

## 보안 메모

`accessToken`은 메모리에만 둔다. 새로고침하면 사라지고 어떤 스토리지에도
남지 않는다.

`refreshToken`은 `sessionStorage`에 둔다. 그래야 새로고침해도 다시 로그인하지
않는다.

**이 값은 JavaScript가 읽을 수 있다.** XSS가 나면 함께 나간다. 제대로 된
방법은 HttpOnly 쿠키인데, 지금 백엔드 인증이 응답 본문으로 토큰을 돌려주는
방식이라 그럴 수 없다. 인증 프로토콜을 바꿔야 닫히는 문제이고, 관리자 웹을
만드는 김에 건드릴 일이 아니라 그대로 두었다. `localStorage` 대신
`sessionStorage`를 쓴 것은 탭을 닫으면 사라지게 해서 노출 시간을 줄이는
정도의 완화다.

브라우저는 `/internal/v1/**` 을 절대 부르지 않는다. 그 경로는 서비스 토큰이
필요하고, 그 토큰을 브라우저에 넣으면 설치본을 뜯는 누구나 갖게 된다.

## 아직 예측이 아니다

수요 예측과 발주 추천에는 실제 모델이 없다. 개발 환경에서는 FastAPI의
fixture가 연결될 수 있고, 그 값은 입력을 보지 않은 고정값이다.

화면은 이 사실을 숨기지 않는다.

- `modelVersion`이 `fastapi-fixture-` 로 시작하면 예측 옆에
  **"개발용 fixture — 실제 AI 예측이 아닙니다"** 배지가 붙는다.
- 발주 추천 화면 상단에는 fixture가 계획 수량을 그대로 돌려줄 수 있다는
  안내가 항상 떠 있다.

숫자가 화면에 있다는 것과 그 숫자를 믿어도 된다는 것은 다른 말이다.

## 식수 예측 (합성데이터 PoC)

대시보드 맨 위의 **중식 예상 인원** 카드. 대시보드에서 식수 예측을 보여 주는
유일한 자리다. 여기서 "식수"는 급식을 먹는 사람 수다.

제목에 "내일"이나 "다음 운영일"을 쓰지 않는다. 관리자가 날짜를 고를 수 있고, 고른
날짜가 실제 다음 운영일인지 화면이 보장하지 않는다. 날짜는 결과에 `2026.09.15 (화)`
처럼 적는다.

```
┌ 중식 예상 인원 ──────────────────── [식수 예측] ┐ ┌ 현재 식당 혼잡도 ┐
│ 2026.09.15 (화)            │ 전일 식수 인원 │ 전주 동일 요일 │ 최근 7일 평균 │ │ 지금 이용 상황 │
│ 431명                      │ 최근 식수 기록: 2026-09-11          │ │ 보통             │
│ 최근 7일 평균 대비 +64명   │ ※ (서버 참고 사항)                  │ │ 현재 인원 …      │
│ 예측 조건 · 2026.09.15 · 화요일 · 2학기 3주차 · 양식 / 돈까스 … [예측 조건 수정] │
│ [AI 예측 PoC] [합성데이터 기반] 현재 식수 예측은 합성데이터 기반 시범 결과입니다. │
└───────────────────────────────────────────────────────────────────┘
관리자 웹 → Spring  POST /api/v1/admin/demand-forecasts/predict · GET …/status
          Spring → FastAPI AI 서버 → 저장된 모델   (브라우저는 이 구간을 모른다)
```

- **시연 흐름(20~30초):** 대시보드 진입 → 요약된 조건 확인 → (필요하면 "예측 조건
  수정"으로 폼을 펼쳐 수정) → "식수 예측" → 예상 인원과 최근 평균·전주 값 비교 →
  옆 카드에서 현재 혼잡도 확인.
- 입력 폼은 기본으로 접혀 있다. 시연 기본 조건(아래)이 미리 채워져 있어 바로 누를 수
  있다. 입력값이 틀리면 예측하지 않고 폼을 펼쳐 고칠 곳을 보여 준다. "기본 조건으로"로
  되돌릴 수 있다.
- 정보 위계: 날짜와 예상 인원 → 최근 7일 평균 대비(단순 산술 차이, 원인 설명 아님) →
  전일 식수 인원·전주 동일 요일·최근 7일 평균과 최근 식수 기록 → 예측 조건 →
  PoC·합성데이터 표시.
- 예측 전에는 숫자 없이 선택한 조건과 안내 문구만 보인다. 결과는 "식수 예측"을 눌러야
  서버 응답으로 채워진다.
- 서버 참고 사항(warnings)은 기록일 아래에 `※ 문구` 로 작게, 서버 문구 그대로 붙는다.
- 모델 상태는 카드가 처음 뜰 때 한 번만 읽는다(주기적으로 다시 읽지 않는다).
  준비되지 않았으면 "식수 예측 모델 준비 중입니다."와 함께 예측 버튼이 잠긴다.
- 예측이 실패하면(Spring 503 등) **"현재 식수 예측을 사용할 수 없습니다."**만
  보인다. 대신할 숫자나 이전 결과를 남기지 않는다. 서버 내부 사유도 옮기지 않는다.
- 응답의 `model.syntheticData`가 true면 카드 맨 아래에 "합성데이터 기반" 표시와
  짧은 안내 **"현재 식수 예측은 합성데이터 기반 시범 결과입니다."** 한 줄이 붙는다.
  서버 `disclaimer`는 버리지 않고 그 안내의 툴팁(`title`)과 화면 낭독기용 텍스트로
  둔다. 같은 뜻의 긴 문장 두 개가 예측값보다 눈에 띄지 않게 하려는 것이다. 모델 버전은
  "AI 예측 PoC" 표시의 툴팁에만 있다.
- **현재 식당 혼잡도(CCTV)는 옆의 별도 카드다.** 식수 예측은 선택한 날짜의 계획, 혼잡도는
  지금 이용 상황이다. 두 결과를 합치지 않고, 예측에 CCTV 효과를 설명으로 붙이지 않는다.
- 브라우저는 Spring 관리자 경로만 부른다. FastAPI 주소·내부 경로·서비스 토큰은
  코드와 번들 어디에도 없다.

예전 대시보드의 "예상 식수" 패널(저장된 끼니별 실행 이력, 대시보드 API의 오늘/내일
값)은 뺐다. 식수 예측이 두 군데에 보이면 어느 숫자가 예측인지 알 수 없다. 끼니별 실행
자체는 발주 추천의 선행 조건이라 **발주 기준 인원** 화면(`/demand`)으로 이름을 바꿔
남겼다. 그 화면은 사이드바에 없고 발주 추천 화면에서만 들어간다.

### 날씨 입력은 D-1 예보값

날씨 API는 연동하지 않았다. 관리자가 예측 시점(전날)에 확보 가능한 예보값(예보 기온·예보
강수량·예보 습도)을 직접 입력한다. API 필드 이름(`temperature`·`rainfall`·`humidity`)은
그대로다.

### 시연

기본 조건: 2026-09-15 · 2학기 3주차 · 시험·행사·공휴일 아님 · 기온 24 · 강수 0 ·
습도 60 · 양식(WESTERN) / 돈까스 · 특식 아님. `src/api/demandForecastPoc.ts`의
`DEMO_DEFAULT_CONDITIONS` 한 곳에 있다(조건만, 결과 숫자는 없다). 이 조건으로 현재 PoC
모델은 **431명**을 낸다. 이 숫자는 코드에 없고 서버 응답에서만 나온다(테스트가 소스를
훑어 확인한다).

실제 서버를 향한 확인(환경 변수가 없으면 건너뛴다). FastAPI → Spring → `npm run dev`를
띄운 뒤:

```
ADMIN_LIVE_BASE_URL=http://127.0.0.1:5173 \
ADMIN_LIVE_PHONE=<관리자 휴대폰> ADMIN_LIVE_PASSWORD=<관리자 비밀번호> \
npx vitest --run src/test/demandForecast.live.test.tsx
```

화면 코드가 Vite 프록시 → Spring → FastAPI를 거쳐 받은 값을 표시하는지, 그리고
화면이 부른 주소가 전부 `/api/v1/` 아래인지 확인한다.

## 값이 없을 때

서버가 `null`을 주면 화면도 비어 있다고 말한다. 0이나 예시 숫자로 메우지
않는다.

- 식수 예측은 누르기 전이나 실패했을 때 숫자 없이 안내 문구만 보인다 (0명 아님)
- 평균 잔반률이 없으면 "데이터 없음" (0% 아님)
- 반복 잔반 메뉴 수는 "판정 기준 미확정" (0개 아님)
- 발주 추천이 비어 있으면 "추천 데이터 없음" (0kg 아님)
- 혼잡도가 없으면 "혼잡도 데이터 없음" (임의로 "보통" 아님)
- 발주 기준 인원 이력이 없으면 "해당 조건의 실행 이력이 없습니다."

## 없는 기능

예약, 픽업, 실시간 재고는 만들지 않았다. 초안 화면설계서에 있던 것이고
서버에 해당 API가 없다. 메뉴에 두면 준비 중인 기능으로 읽힌다.

설문은 등록과 결과 조회만 있다. 수정·삭제 API가 없어서 버튼도 만들지 않았다.

## 잔반 인증 검증 (수동)

잔반 인증은 AI가 판정하지 않는다. 사용자가 사진을 올리면 PENDING 상태로 쌓이고, 관리자가 `/waste-submissions` 에서 사진을 직접 보고 승인하거나 거절한다. 처음 승인하면 사용자에게 100 포인트가 지급되고, 승인은 되돌릴 수 없다(승인된 건은 거절 불가, 서버가 409). 거절하면 포인트가 없다.

- 사진은 Authorization 헤더가 필요해 `<img src>` 로 열 수 없다. 인증 클라이언트(`requestBlob`, 401 갱신 포함)로 Blob 을 받아 object URL 로 보여 주고 닫을 때 해제한다.
- 전화번호는 서버가 가려서 준 값(`010-****-5678`)만 표시한다.
- 폴링은 없다. 창에 다시 돌아왔을 때와 승인/거절 직후에만 목록을 다시 불러온다.
